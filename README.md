# IPG4Lattice

Utilities and notes for implementing the Integrated Polyakov gauge (IPG) on top of already Coulomb-gauge-fixed lattice ensembles, plus local analysis scripts for gauge-fixed quark propagators and momentum-space Green's functions.

## Current scope

- `v1` targets the `S16T16` Coulomb-gauge-fixed ensemble in `ensemble/S16T16_cg/gauge`.
- The source paper is [`doc/1204.0716v2.pdf`](/home/jinchen/git/anl/IPG4Lattice/doc/1204.0716v2.pdf), especially Appendix A.
- The detailed project spec is in [`SPEC.md`](/home/jinchen/git/anl/IPG4Lattice/SPEC.md).
- Agent workflow and coding rules are in [`AGENTS.md`](/home/jinchen/git/anl/IPG4Lattice/AGENTS.md), with development history in [`PROJECT_LOG.md`](/home/jinchen/git/anl/IPG4Lattice/PROJECT_LOG.md).

- `doc/1204.0716v2.pdf`: reference paper.
- `scripts/ipg_utils.py`: shared IPG and validation helpers.

- `scripts/validate_cg_ipg.py`: definition-level CG -> CG+IPG validation and diagnostics.
- `scripts/qprop_static.py`: wall-source tdir and point-source zdir quark propagator. Plots both effective masses and caches raw data to `artifacts/data/`.
- `scripts/qprop_mom.py`: staggered momentum-wall-source time-direction quark propagator with spatial momentum projection via `MomentumPhase`. Plots effective masses for staggered taste insertions (I, gX, gY, gZ, gT) at each momentum.
- `scripts/qprop_greens.py`: fully Fourier-transformed quark Green's function `G_Gamma(p) = Nc Tr[Gamma S(p)]` at selected 4-momenta (temporal momenta 0..T/2) for all five gamma insertions. Caches complex-valued results to `artifacts/data/`.
- `scripts/qprop_fig3_mass.py`: fresh Fig. 3-style mass-function scan from CG+IPG gauge files. It does not read existing `.npz` analysis data; outputs are saved only as a record of the run.
- `scripts/qprop_utils.py`: staggered momentum-space pipeline (wall source + FFT → `G_Γ(p)` → `A_s`/`B_m` → Eq. 25 `M(|k|)`). See module docstring for the step-by-step map.
- `scripts/qprop_M.py`: runner for dense-grid `M(|k|)` and bare-mass scans on CG+IPG ensembles. Outputs `artifacts/data/qprop_M_{ensemble}.npz` and `artifacts/plots/qprop_M_{ensemble}*.pdf` (`M`, optional GeV, `As`, `Bm` at `reference_mass`).
- `ensemble/`: local input and generated ensembles. The entire directory is ignored by git.
- `artifacts/plots/`: local plots generated by the analysis scripts.
- `artifacts/data/`: cached per-configuration correlator and Green's function data for reuse across scripts.

## IPG implementation

The current implementation follows Appendix A of the paper on top of an already Coulomb-gauge-fixed ensemble:

1. Read a Coulomb-gauge-fixed NERSC gauge field.
2. For each time slice `t`, compute the spatial average of the temporal links
   `û(t) = (1/L^3) Σ_x U_4(x,t)`.
3. Project `û(t)` back to `SU(3)` using a Cabibbo-Marinari subgroup projection to obtain `u(t)`.
4. Build the integrated Polyakov matrix `P = ∏_t u(t)`.
5. Compute a constant target matrix `C = P^(1/T)` using `scipy.linalg.logm/expm`, with a `Z_3` branch choice selected by the best periodic closure.
6. Set `g(0) = I` and recursively construct the residual time-only gauge transformation
   `g(t+1) = C† g(t) u(t)`.
7. Apply the residual transform
   `U'_i(x,t) = g(t) U_i(x,t) g†(t)` and
   `U'_4(x,t) = g(t) U_4(x,t) g†(t+1)`.
8. Write the resulting `CG+IPG` gauge only into a new output root, leaving the original CG ensemble untouched.

The implementation uses the matrix product interpretation of Appendix A:
`P^(1/T)` is taken from the `SU(3)` matrix `P = ∏_t u(t)`, not from a traced scalar Polyakov loop.

Current numerical choices for the IPG step are:

- The residual IPG construction is carried out in double precision (`numpy`/`scipy` complex128).
- The Cabibbo-Marinari projection sweep stops at an internal tolerance of `1e-14`.
- The `SU(3)` projection is required to satisfy a unitarity check at the `1e-10` level.
- The `--projection-method` flag controls both the transform construction and the post-IPG verification metrics (`post_spread`, `target_dev`), so that fixing and validation use the same projection throughout.  The default is `cabibbo-marinari`, following the convention of Appendix A of 1204.0716.
- The determinant-one normalisation used throughout (`matrix / det(matrix)^(1/3)`) adopts the **principal complex cube root** convention, i.e. `det^(1/3) = |det|^(1/3) exp(i arg(det)/3)` with `arg ∈ (-π, π]`.  This fixes one `Z_3` branch at the normalisation step; the remaining branch ambiguity in the `P^(1/T)` construction is resolved separately by the `Z_3` candidate selection described below.
- A `Z_3` center alignment step is applied after every `SU(3)` projection of the post-IPG temporal-link averages.  The alignment step picks the center phase that minimises the Frobenius distance to the target matrix `C`, eliminating spurious `Z_3`-branch jumps.  Post-transform diagnostics (`post_spread`, `target_dev`) are therefore `Z_3`-aligned to `C` before comparison, so they are insensitive to the branch choice made during construction.
- In practice the resulting IPG diagnostics are usually observed at around `1e-14` to `1e-13`, while the final ensemble quality is still limited by the precision of the input Coulomb-gauge fixing.

## IPG validation

`scripts/validate_cg_ipg.py` performs definition-level validation rather than relying only on propagator plots. For each configuration it rebuilds the IPG transform from the original CG gauge and checks the written `CG+IPG` gauge against the Appendix A conditions.

The reported diagnostics are:

- `pre_spread`: spread of the projected temporal-link averages before IPG.
- `post_spread`: spread of the projected temporal-link averages after IPG, measured with `Z_3` alignment to the target matrix. This should be small if the time-slice averages have been flattened to a constant.
- `boundary`: periodic closure error of the recursive `g(t)` construction.
- `residual`: maximum violation of `g(t) u(t) g†(t+1) = C`.
- `target_dev`: maximum deviation of the post-IPG projected temporal-link averages from the target constant matrix `C`, with `Z_3` alignment applied before comparison.
- `reconstruct`: maximum link-wise difference between the written `CG+IPG` gauge and the gauge reconstructed directly from the original CG gauge using the implementation.
- `target_u`, `polyakov_u`, `transform_u`: unitarity checks for the target matrix, integrated Polyakov matrix, and residual transform.
- `target_det`, `polyakov_det`, `transform_det`: determinant checks for the same objects.
- `logm_err`: numerical error reported by the matrix-logarithm step used to construct `P^(1/T)`.

The default acceptance criteria are controlled by `--spread-tol`, `--boundary-tol`, and `--reconstruct-tol`.

The current default validation tolerances are:

- `--spread-tol = 1e-10`
- `--boundary-tol = 1e-10`
- `--reconstruct-tol = 1e-10`

## Quark propagator tests

The quark-propagator scripts are kept as supplementary physics sanity checks on top of the definition-level validation.

IPG only constrains the spatially-averaged temporal links `u(t)`, so only the spatially-averaged (wall-source) time-direction quark propagator carries a clean signal after IPG. All tdir propagator scripts therefore use wall sources.

- `scripts/qprop_static.py`: wall-source tdir quark propagator (spatially averaged) plus point-source zdir propagator from the origin. Caches both to `artifacts/data/qprop_static_{ensemble}.npz`.
- `scripts/qprop_mom.py`: **staggered** momentum-wall-source tdir quark propagator with spatial momentum projection. For each momentum `p`, uses a wall source at `t=0` with source phase `exp(-ip·x)` and sink phase `exp(+ip·x)`, giving L³ better statistics than a point source. Uses staggered taste insertions (I, gX, gY, gZ, gT) and plots the effective mass for each momentum.
- `scripts/qprop_dispersion_check.py`: offline check of `E_eff(p)` vs `√(M(|k|)² + |k|²)` from cached `qprop_mom` and `qprop_M` data (PDF only).
- `scripts/qprop_greens.py`: fully Fourier-transformed quark Green's function `G_Gamma(p) = Nc Tr[Gamma S(p)]` at selected 4-momenta (temporal momenta `n4 = 0..T/2`) for all five gamma insertions. Caches the complex-valued Green's functions per gamma to `artifacts/data/qprop_greens_{ensemble}.npz`.
- `scripts/qprop_fig3_mass.py`: remeasures from gauge files and plots `M(|k|)` in lattice units for a bare clover-mass scan. Since the current `S16T16` ensemble has no scale setting, the script intentionally avoids GeV/MeV labels and treats `mass` as a bare input parameter.
- `scripts/qprop_M.py`: staggered wall-source `M(|k|)` with physical-branch shells and Eq. 25 p4 averaging. Pipeline details in `scripts/qprop_utils.py`. Coefficient diagnostics (`As`, `Bm`, pointwise `M(p)`) use a fixed 12-point `(px,py,pz,pt)` grid (4 spatial shells × `pt ∈ {0,4,8}`). Edit parameters at the top of `qprop_M.py` or use CLI flags.

In practice the intended checks are:

- Check that the temporal-direction quark propagator develops a visible signal once the residual gauge freedom is fixed.
- Use the momentum-projected and fully Fourier-transformed scripts as additional diagnostics when exploring gauge-fixed quark Green's functions away from zero momentum.
- Examine the Dirac structure of the momentum-space propagator: the `G_Gamma(p)` traces encode the dressing functions `A_s`, `A_t`, `B_m` of the inverse propagator (Eq. 20 of the reference paper), which should be approximately independent of `p4`.

## Typical workflow

Generate CG+IPG gauges:

```bash
python scripts/ipg_fix.py \
  --input-dir ensemble/S16T16_cg/gauge \
  --output-dir ensemble/S16T16_cg_ipg \
  --glob 'wilson_b6.cg.1e-08.*' \
  --save-transform \
  --verify-readback
```

Validate the Appendix A definition against the written CG+IPG ensemble:

```bash
python scripts/validate_cg_ipg.py \
  --cg-dir ensemble/S16T16_cg/gauge \
  --ipg-dir ensemble/S16T16_cg_ipg/gauge \
  --glob 'wilson_b6.cg.1e-08.*' \
  --n-conf 1
```

If a written `CG+IPG` gauge has `post_spread` above tolerance, validation can optionally rebuild that configuration from the original `CG` gauge and overwrite the failing output:

```bash
python scripts/validate_cg_ipg.py \
  --cg-dir ensemble/S16T16_cg/gauge \
  --ipg-dir ensemble/S16T16_cg_ipg/gauge \
  --glob 'wilson_b6.cg.1e-08.*' \
  --repair-spread \
  --repair-max-iters 3
```

When `--repair-spread` is enabled, the sibling `ipg_transform/*.npy` archive is also rewritten so that the saved residual gauge transformation matches the repaired `CG+IPG` gauge.

Run the quark-propagator and Green's-function analysis scripts:

```bash
python scripts/qprop_static.py
python scripts/qprop_mom.py
python scripts/qprop_greens.py
```

Run paper-style staggered `M(|k|)` (PyQUDA / GPU required):

```bash
/home/jinchen/miniconda3/envs/pygpt/bin/python scripts/qprop_M.py --ensemble S24T24_cg_ipg --n-conf 50
/home/jinchen/miniconda3/envs/pygpt/bin/python scripts/qprop_M.py --ensemble S24T24_cg_ipg --replot-only
```

Run a fresh Fig. 3-style mass-function scan without reading existing `.npz` analysis data:

```bash
/home/jinchen/miniconda3/bin/conda run -n pygpt python scripts/qprop_fig3_mass.py \
  --gauge-dir ensemble/S16T16_cg_ipg/gauge \
  --glob 'wilson_b6.cg.ipg.1e-08.*' \
  --n-conf 50 \
  --masses -0.08,-0.06,-0.038888,-0.02,0.0 \
  --tag mass_scan \
  --overwrite
```

For the `S32T32_cg_ipg` ensemble, where `a` is roughly `0.1 fm`, the same script can infer the `32^4` volume and plot a middle-momentum window in GeV:

```bash
/home/jinchen/miniconda3/bin/conda run -n pygpt python scripts/qprop_fig3_mass.py \
  --ensemble S32T32_cg_ipg \
  --gauge-dir ensemble/S32T32_cg_ipg/gauge \
  --glob 'wilson_b5_95_fixed.*.ipg' \
  --n-conf 5 \
  --masses -0.08,-0.06,-0.038888,-0.02,0.0 \
  --a-fm 0.1 \
  --min-k-gev 0.8 \
  --max-k-gev 2.5 \
  --tag mid_a0p1 \
  --overwrite
```

The Fig. 3 script keeps the spatial physical branch by default with `--max-mode-fraction 0.25`, i.e. it excludes spatial Fourier modes near the Brillouin-zone edge before grouping by `|k| = sqrt(sum_i sin(p_i)^2)`. This avoids averaging low-momentum shells with `sin(p)`-degenerate doubler shells.

Interpretation of this plot is intentionally limited. A successful run should reproduce a Fig. 3-style `M(|k|)` plot with low-momentum mass enhancement and sensible ordering under the bare-mass scan, but it is not expected to numerically overlay the paper. The current `S16T16` data have no scale setting, the valence action here is clover rather than the paper's main staggered/Asqtad setup, the bare `mass` values are not tuned to physical quark masses, and the small `16^4` volume gives coarse momentum resolution. These differences are the expected sources of mismatch with the published GeV-scale curves.

## Output conventions

- Input CG ensemble: `ensemble/S16T16_cg/gauge/wilson_b6.cg.*`
- Output root passed to `scripts/ipg_fix.py --output-dir`: `ensemble/S16T16_cg_ipg`
- Output CG+IPG ensemble: `ensemble/S16T16_cg_ipg/gauge/wilson_b6.cg.ipg.*`
- Saved residual time-only gauge transformation `g(t)` from the original `CG` gauge to the written `CG+IPG` gauge: `ensemble/S16T16_cg_ipg/ipg_transform/*.npy`
- `scripts/ipg_fix.py` automatically creates the sibling `gauge/` and `ipg_transform/` directories under the output root.
- Local analysis plots: `artifacts/plots/*.pdf`
- Cached analysis data: `artifacts/data/*.npz`

Generated ensemble files, plots, and cached data are intentionally ignored by git.

## Notes

- `scripts/validate_cg_ipg.py` now reports definition-level diagnostics such as `post_spread`, `boundary`, `residual`, and `reconstruct`.
- All post-IPG projection metrics (`post_spread`, `target_dev`) are `Z_3`-aligned to the target matrix `C`, so configurations whose Cabibbo-Marinari projection lands on a different center branch are handled correctly rather than producing a spurious spread of `3.0`.
- `--cfg-start/--cfg-stop` filter by the trailing configuration index, so combine them with `--glob` if multiple solver tolerances exist for the same configuration number.
- QUDA, CUDA, MPI, and GPU driver compatibility are not fully portable; adjust [`environment.yml`](/home/jinchen/git/anl/IPG4Lattice/environment.yml) to match your local system.
